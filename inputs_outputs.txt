INPUTS / OUTPUTS - exact, runnable examples for Canonical Repair Profiler (CRP)

The submission video runs these LIVE via the dashboard (app.py):
  - Tab "Claim Assistant": F-150 -> part 6148 executes EXAMPLE 4 (incoming-claim inference),
    with an optional dealer-state selector that executes EXAMPLE 5 (regional localization).
  - Tab "Agent Pipeline": "Super Duty Oil Pan" executes EXAMPLE 2 (the reseal-vs-replace split),
    "F-150 Engine Long Block" executes EXAMPLE 1 (single repair).

  - Segment E (error handling): EXAMPLE 12 (no-match -> manual review) runs live in the dashboard;
    EXAMPLES 13-15 demonstrate region fallback, API retry/timeout, and the LLM over-split guard.

Every example is also runnable from the CLI below. EXAMPLE 0 and EXAMPLES 12-15 run with NO cloud.

EXAMPLE 1  (LIVE DEMO) - produce a Canonical Repair for one repair signature
--------------------------------------------------------------------------------
COMMAND (input):
    python cli.py run --signature 32954        # (or: python -m src.agents.orchestrator --signature 32954)

WHAT HAPPENS (agent hand-off chain, all live):
    GroupingAgent      -> loads signature 32954 (P552N F-150 [15-20], causal part 6148) + 961 claims
    ConsensusAgent     -> cost/labor consensus + IQR bands (deterministic)
    RepairAnalystAgent -> Vertex AI Gemini decides #repairs + writes diagnosis + correction
    SolutionAssemblyAgent -> fuses LLM text with per-tier numbers -> golden solution
    SolutionCriticAgent -> QA gate: PASS/FLAG/FAIL verdict; text defects go BACK to the
                           RepairAnalystAgent for one bounded revision round
    CostSavingsAgent   -> adds avoidable-overspend vs consensus

OUTPUT (observed; LLM prose varies slightly run-to-run, fields are fixed):
    [
      {
        "signature_id": 32954, "vehicle_line": "P552N F-150 [15-20]", "causal_part": "6148",
        "n_repairs_detected": 1, "repair_name": "Long Block Engine Replacement", "cost_tier": "all",
        "unified_diagnosis": "Excessive oil consumption, engine noise/rough running due to internal wear.",
        "suggested_correction": "Replace the engine long block assembly to restore function.",
        "typical_parts": "Engine long block assembly",
        "labor_med_hrs": 16.8, "cost_med": 8923.13, "cost_q25": 7835.16, "cost_q75": 10378.93,
        "consensus": 0.779, "support": 961, "confidence": 0.779,
        "savings_per_claim": 1005.62, "savings_pct_claims_above": 50.0, "usable": true,

--------------------------------------------------------------------------------
EXAMPLE 14  (EDGE - API TIMEOUT / TRANSIENT FAILURE) - retry-with-backoff + graceful error
--------------------------------------------------------------------------------
COMMAND (input):
    python -m pytest tests/test_vertex_gemini_tool.py -q

OUTPUT (observed): 7 passed - these tests drive the exact live fallback behavior of VertexGeminiTool:
    - transient 429/5xx/timeout/401  -> retry with backoff, then succeed
    - malformed (non-JSON) response   -> reported as {_ok: False, error}, not retried forever
    - fatal 400                       -> fast-fail (not retried)
    - retries exhausted               -> graceful {_ok: False, error}; generate_text -> "[LLM_ERROR] ..."
    (Live, the agent therefore never crashes the pipeline on an API hiccup; a stuck call is
     killed by the 60s timeout and a failed group falls back to a single-repair shell.)

--------------------------------------------------------------------------------
EXAMPLE 15  (EDGE - LLM OVER-SPLIT / HALLUCINATION) - deterministic separation guard
--------------------------------------------------------------------------------
COMMAND (input):
    python -m pytest tests/test_solution_assembly.py -q

OUTPUT (observed): 5 passed - the SolutionAssemblyAgent's validation loop protects against the LLM
proposing a split that the data does not support:
    - a proposed 2-way split is honored ONLY if the high cost tier is >= 1.5x the low tier
    - otherwise it collapses to ONE repair, with split_rationale "... were not separated ..."
    (So the agent never reports two repairs that are really one repair with normal price variation.)

NOTES
--------------------------------------------------------------------------------
* Offline (EXAMPLE 0, EXAMPLES 7-11, and EXAMPLES 12-15): set CRP_USE_SAMPLE=1 - no credentials/network.
* Live (EXAMPLES 1-6): `gcloud auth login` first (Ford CAA needs interactive user creds; the tools
  auto-refresh the token).
* Numeric fields (labor/cost bands, consensus, savings, region index) are deterministic from the data
  (StatsTool / RegionIndexTool); only diagnosis/correction/name prose is LLM-generated.
